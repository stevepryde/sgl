# Provenance and algorithm notes

The initial Rust/WGSL implementation was ported from DiligentFX revision
`f26cfe5b901bf180c4a3c9bbd4d5df0b96536d4b` and
DiligentCore revision `18bfa7b7563a0ef5b5fe074d37c2e8304100e965`
(`HLSLDefinitions.fxh`), retained unedited in `vendor/`.

`sgl-post-fx` is now an SGL-owned effects library, evolving under
[RD-2](../../specs/sgl3d.md#rendering-development). Upstream equivalence and
feature parity are not requirements. Keep source attribution and licences,
and maintain notes when they explain an algorithm or implementation decision;
new changes do not require an exhaustive difference catalogue.

The notes below preserve the original port's adaptations and subsequent fixes.
The DFX identifiers remain stable because code and tests refer to them. They
are historical references, not an approval process or a claim that unlisted
code matches upstream.

| ID | Upstream | Here |
| --- | --- | --- |
| DFX-1 | `SupportedDeviceFeatures` depend on the device (D3D, Vulkan, GL, WebGL). | Fixed for wgpu: texture subresource views, no depth-to-colour copies (depth reaches the hierarchy through `CopyTextureDepth`), the base vertex in `vertex_index`, no explicit transitions (wgpu tracks them). Only those paths are ported; the WebGL paths (`SUPPORTED_SHADER_SRV` 0, the intermediate hierarchy texture, the index-buffer blue-noise draw) are omitted. `FEATURE_FLAG_HALF_PRECISION_DEPTH` needs wgpu's `TEXTURE_FORMAT_16BIT_NORM` for its R16Unorm depths. |
| DFX-2 | Asynchronous shader and pipeline creation (`EnableAsyncCreation`, `IRenderStateCache`), `POST_FX_EXECUTION_STATUS_PENDING` and the placeholder output while compiling. | wgpu creates pipelines synchronously; a created pipeline is ready. TAA still reads readiness in `PrepareResources`, before `Execute` creates its pipeline, so as upstream its first frame for a feature set copies the input and reports pending. The transition timer (`Timer`) is `std::time::Instant`. |
| DFX-3 | `PackMatrixRowMajor`. | Not ported: matrices follow the translation rule in README.md. |
| DFX-4 | `ScreenSpaceReflection::UpdateUI` and `TemporalAntiAliasing::UpdateUI` (ImGui). | Not ported. |
| DFX-5 | Resource binding through shader resource bindings and named variables; `Texture2D<float>` depth SRVs; a missing accumulation buffer logs an error and fails. | One bind group per pass, created when it draws, at the binding numbers the WGSL declares. Depth-buffer inputs bind as `texture_depth_2d`; textures read only with `Load` bind as unfilterable float. A missing accumulation buffer panics with upstream's message. |
| DFX-6 | `[earlydepthstencil]` on the passes that test the reflection mask. | No WGSL equivalent. Those passes neither discard nor write depth, so the depth test already precedes shading. |
| DFX-7 | `CopyTexturePS` samples any `Texture2D`. | It is a depth or colour permutation because WGSL types the texture (`CopyTextureDepth` and `ComputePreviousDepth` read depth buffers). |
| DFX-8 | `DeviceContext::UpdateBuffer` and `MapHelper` write constants in the command stream. | `Queue::write_buffer`, which lands before the submission's commands; equivalent for one execution per submission. |
| DFX-9 | SSR's and TAA's temporal accumulation and the reprojected depth read `g_CurrCamera` and `g_PrevCamera` from one constant buffer. | One uniform of both cameras: `cbCameraAttribs.g_CurrCamera`, `cbCameraAttribs.g_PrevCamera`. |
| DFX-10 | `ScopedDebugGroup` around each pass. | `RenderAttributes::pass_timestamps` supplies timestamp writes by the same names, for per-pass GPU timing; `TextureOperationAttribs::timestamp_writes` carries them into the context's copies and clears. |
| DFX-11 | Internal textures (TAA's accumulated buffers included) are shader resources and render targets. | They also allow copies (`COPY_SRC`) so callers can capture intermediate results. |
| DFX-12 | SSR has no history reset; its histories are cleared only when `PrepareResources` creates them. | SSR resets them by the rule DiligentFX's TAA uses (`TemporalAntiAliasing::AccumulationBufferInfo::UpdateConstantBuffer`): on the first execution, when the frame index is not the last one plus one (skipped frames), or when `RenderAttributes::reset_accumulation` asks. A reset clears the four histories as creation does, so the frame equals a new effect's. Owner decision 2026-09-28. |
| DFX-13 | `PostFXContext::Execute` always computes the closest motion vectors. | `CreateInfo::compute_closest_motion` (default true) can skip them for callers without an effect that reads them. Owner decision 2026-09-28. |
| DFX-14 | TAA's `MotionFactor` (pixel speed) scales both the variance gamma and the history weight, so any pixel moving faster than 1/`TAA_MOTION_VECTOR_DIFF_FACTOR` of the viewport per frame loses its history. That contradicts the constant's documentation ("the difference in motion vectors between the current frame and the previous frame"). | The history weight uses the difference between the pixel's motion and the previous frame's closest motion at its reprojected position, with the same constant, as documented and as Godot's TAA rejects ("velocity disocclusion"). Speed still sets the variance gamma, as the README describes. `TemporalAntiAliasing` keeps the previous closest motion per accumulation buffer, copied with `CopyTextureColor` after each execution, and binds it as `g_TexturePrevMotion`. Owner decision 2026-09-28. |
| DFX-15 | `ScreenXYDepthToViewSpace` (`PostFX_Common.fxh`) divides NDC by the projection's scale only and drops its off-centre terms, while `ProjectPosition` applies the whole matrix. Hydrogent passes the TAA-jittered projection (`TemporalAntiAliasing::GetJitteredProjMatrix` adds the jitter to `m20` and `m21`). SSR's screen-space ray therefore bends by the jitter scaled by its length, and the hit reads radiance texels away from the reflected point, differently each frame. | The reconstruction subtracts `m20` and `m21` from NDC first, the exact inverse of the projection in x and y. AMD's SSSR reconstructs the same way with its full inverse projection (`FFX_SSSR_ScreenSpaceToViewSpace`). Upstream bug fix, 2026-09-28. |
| DFX-16 | `SSR_ComputeSpatialReconstruction` averages raw radiance. The pass is Wicked Engine's `ssr_resolveCS` (the same BRDF-over-PDF ray reuse, weighted variance and ray-length reprojection depth) without its tone mapping, so one ray that hits an emitter dominates a glossy pixel's average. With `TemporalRadianceStabilityFactor` 1.0, the temporal pass clamps history to a neighbourhood box that such outliers widen and narrow. A static glossy reflection of bright emitters then sparkles, and its mean falls several times below the resolved radiance. | Samples are tone-mapped by 1/(1 + luminance) before the weighted average and variance, and the average is inverse tone-mapped, as Wicked's `ssr_resolveCS` does. The weight applies to confidence as well as colour, so the premultiplied radiance of DFX-17 stays consistent: the round trip is a luminance-weighted average of whole samples. A receiver whose reconstruction radius is under half a texel (perceptual roughness under 0.025) resolves only its own ray, which the round trip leaves unchanged. Fixes the static SSR sparkle the owner reported, 2026-09-28. |
| DFX-17 | `SSR_ComputeIntersection` stores a hit's full radiance whenever its confidence is above zero, and black for a miss, with the confidence in alpha. The spatial pass averages rays, so the colour carries the share of rays that hit but not their partial confidence. Hydrogent then composites `lerp(IBL, SSR, alpha)`, as Wicked does. That scales hits by the hit share twice and weak hits not at all, so reflected light fades too early and too dark wherever only some of a pixel's rays hit. | Each ray stores its radiance premultiplied by its confidence, so every average keeps colour and confidence consistent, and the transition fade (`AlphaInterpolation`) scales both. A consumer composites `radiance + (1 - confidence) * environment`, as Bevy composites its SSR, and as AMD's SSSR blends the environment into each missed ray. Owner decision 2026-09-28. |
| DFX-18 | `HierarchicalRaymarch` (`SSR_ComputeIntersection`, AMD's FidelityFX SSSR traversal) treats the depth buffer as infinitely thick: a ray ends at the first surface it passes behind. `ValidateHit` then rejects a hit more than `DepthBufferThickness` behind that surface, so every ray that passes behind a thin foreground object (a pole, a vehicle) on its way to a farther reflected surface falls back to the environment. | At the most detailed mip, a ray behind the surface by at least `DepthBufferThickness` (measured as `ValidateHit` measures it, where its confidence reaches zero) advances to the next cell at the same mip and continues, as Godot's hierarchical SSR does with its depth tolerance (`servers/rendering/renderer_rd/shaders/effects/screen_space_reflection.glsl`, revision `d851ae838de54a0bd3dde9043912f39c74265cdd`, MIT, `LICENSE-godot.txt`). Hits `ValidateHit` accepted are unchanged. Owner decision 2026-09-29. |
| DFX-19 | `TAA_ComputeTemporalAccumulation` keeps at most `TemporalStabilityFactor` (0.9375) of history and rejects it by depth disocclusion at every pixel. The depth buffers it compares are rendered with different jitter, so with the camera still, sub-pixel geometry (distant light strips) changes depth between frames: its history is rejected every few frames and it blinks. The remaining 1/16 current weight leaves jittered detail and reflections shimmering in a still image. | A pixel whose closest motion is under 0.01 pixels on both axes keeps up to 0.985 of history and skips the depth test, as Bevy's TAA does for pixels that are not moving (`crates/bevy_anti_alias/src/taa/taa.wesl`, revision `92a29e701a6b0bf8846484c3999c2ba97d90dd06`, MIT, `LICENSE-bevy.txt`: `MIN_HISTORY_BLEND_RATE` 0.015, no depth rejection). Moving pixels are unchanged. Owner request 2026-09-29 (visible jitter while stopped). |
| DFX-20 | `SampleReflectionVector` (`SSR_ComputeIntersection`) moves the second random number to 0 by `GGXImportanceSampleBias`. Under the spherical-cap VNDF sampler (`SmithGGXSampleVisibleNormalSC`, Dupuy and Benyoub 2023) that is the cap's pole, so at bias 1 the micro-normal is the normalised sum of the roughness-stretched view direction and the normal. It tilts towards the viewer by an angle that grows with roughness and towards grazing view, so rays rise above the mirror direction: at perceptual roughness 0.125 by about a fifth of their elevation 2° above the surface. Reflections far along a glossy floor are squashed towards what they reflect and stretch back as the camera approaches. | At bias 1 the micro-normal is the macro normal, so the ray follows the mirror direction, the lobe's peak, as Godot's SSR traces `reflect(view_dir, normal)` (`servers/rendering/renderer_rd/shaders/effects/screen_space_reflection.glsl`, revision `ed1daf0bf001b61586d9930840f2f1394092c079`, 4.7.2-stable, MIT, `LICENSE-godot.txt`); its PDF is evaluated there. Bias below 1 is unchanged. Owner request 2026-09-29 (distant reflections warping as the camera approaches). |
| DFX-21 | `SSR_ComputeStencilMaskAndExtractRoughness` discards rejected pixels before exporting roughness, although the half-resolution mask reads all pixels in a block. Preserved roughness can describe an earlier frame. | Export current roughness for every pixel and write the existing depth eligibility mask explicitly as 0/1 in the same pass. Full-resolution eligibility is preserved. The upstream maximum-roughness reduction is retained: a half-resolution block traces only when every contributing roughness is eligible, including current rough/background values, rather than retaining a previous glossy value. Full-resolution bilateral cleanup likewise excludes newly rough neighbors. This fixes stale input data (#313); the conservative half-block policy remains upstream's. |
| DFX-22 | Hierarchical raymarching validates unfinished budget endpoints with proximity confidence, as AMD FidelityFX SSSR does. | Preserve upstream budget acceptance. Stop traversal on viewport exit, as [AMD's hybrid traversal](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK/blob/c6efa6bf7f2027b3ec94f28578bb5965eabb9e55/samples/hybridreflections/shaders/ffx_sssr_intersect.h#L139-L158) does; `ValidateHit` already assigns zero confidence outside the viewport. The miss endpoint now stops at the first exit, so its shorter ray length can affect the confidence-independent `NearestSurfaceHitDistance` used by spatial reconstruction. This is an early-out optimization, not an upstream exhaustion bug fix (#312 review correction, 2026-09-30). |
| DFX-23 | `ComputeSpatialReconstruction` preserves its render targets outside the reflection mask; `ComputePixelStatistic` in temporal accumulation reads every member of the current 3×3 neighbourhood. A newly rough or background neighbour can therefore contribute a departed bright reflection and permit obsolete bright history at an active dark pixel (stevegame #314). | Clear the reconstruction targets to zero in the existing render pass before writing active pixels, as the intersection pass already does. Current neighbourhood statistics cannot consume older skipped samples; temporal histories and their accumulation remain intact. AMD FidelityFX SSSR's resolved-radiance analogue is its [Prefilter output](https://github.com/GPUOpen-Effects/FidelityFX-Denoiser/blob/d7dfecbabe7b9523b14e7b067216e06b86e8d189/ffx-reflection-dnsr/ffx_denoiser_reflections_prefilter.h) (the denoiser revision pinned by SSSR `34dcacd1feefcfab2855b82e76c7d711f2020a75`): the denoiser writes every pixel in a dispatched tile, copying current intersection radiance for non-reflective pixels. SGL3D supplies environment radiance separately, so rejected reconstruction pixels are zero here. No AMD code is copied. |
| DFX-24 | `ScreenSpaceReflection::m_FrameTimer` (Diligent's `Timer`) reads the system clock for the transition alpha's elapsed time, restarted while pipelines are pending. | The caller passes `RenderAttributes::frame_time`, the seconds since the previous execution, and the elapsed time is their sum since the restart, 0 at the first execution. The browser forces it: `wasm32-unknown-unknown` has no clock, and `std::time::Instant::now` panics there. When `frame_time` is the measured time between executions, the sum is upstream's elapsed time from the second execution on; upstream's timer starts at construction, so its first execution reads the short time since then. |
| DFX-25 | `TemporalAntiAliasingStructures.fxh` fixes TAA's history rejection and variance clip at compile time: `TAA_MIN_VARIANCE_GAMMA` 0.75, `TAA_MAX_VARIANCE_GAMMA` 2.5, `TAA_MOTION_VECTOR_DIFF_FACTOR` 256, `TAA_DEPTH_DISOCCLUSION_THRESHOLD` 0.9 and `TAA_VARIANCE_INTERSECTION_MAX_T` 10. | They are `TemporalAntiAliasingAttribs` fields after upstream's (`min_variance_gamma`, `max_variance_gamma`, `motion_vector_diff_factor`, `depth_disocclusion_threshold`, `variance_intersection_max_t`), with those values as defaults, so a caller tunes them per frame as it does `TemporalStabilityFactor`. DFX-19's still-pixel constants are fields too (`still_motion_pixels` 0.01, `still_history_factor` 0.985). The structure grows from 16 to 48 bytes. Owner request (#52), 2026-10-04. |
